# Prototype บน Design canvas

ไฟล์นี้บอกว่าควรวางอะไรไว้บน canvas ส่วนรูปแบบไฟล์ (`.dc.html`, `canvas.json`, การส่งไฟล์) ให้ใช้ตามคำแนะนำของ Design type ที่ได้มาตอนสร้าง canvas ถ้าขัดกัน ให้ทำตามคำแนะนำของ type

## Page

| page id | ชื่อ | มีอะไร |
|---|---|---|
| `prototype` | Prototype | หน้าจอทั้งหมด จัดเป็นแถว |
| `features` | Feature list | `Feature-List.dc.html` ที่ script สร้าง (`expand: "fill"`, w 1280, h ประมาณ 60 px × จำนวนฟีเจอร์ + 1500) |

ตั้ง `launch` เป็น `{"view":"canvas"}`

## แถวบน Prototype

หนึ่งแถวต่อหนึ่งส่วนของระบบ หรือหนึ่ง flow หลัก แต่ละแถวมี note `kind: "title1"` อยู่เหนือแถว:

| แถว | เนื้อหา | ขนาดต่อหน้าจอ |
|---|---|---|
| 0 · Website (desktop) | Home, เมนู, หมวดสินค้า, หน้าสินค้า, support, หน้าบัญชี | 1440 กว้าง, `expand: "fill"`, สูงตามเนื้อหา |
| 1 · App: flow หลักที่เป็นจุดขาย | เช่น สแกน QR → ลงทะเบียน → เสร็จ → สถานะ | 390 × 844, `radius: 28` |
| 2 · App: ซื้อขาย | Home, หมวด, สินค้า, ตะกร้า, บัญชี, สั่งซื้อเสร็จ, คืนสินค้า | 390 × 844 (หน้ายาวใช้สูงเท่าเนื้อหา) |
| 3 · Back office และ AI | Dashboard, คิวงาน, ข้อมูลลูกค้า, ตั้งค่า | 1280 × 940, `expand: "fill"` |

ตัดแถวที่งานไม่มี เพิ่มแถวเมื่อมี flow หลักอีกชุด (เช่น แอปช่าง) ระยะห่างระหว่างหน้าจอในแถว 80 px ระหว่างแถว 120 px บวกที่ว่างสำหรับ title

## ชื่อหน้าจอ

- รหัส `<แถว>.<ลำดับ>` ตรงกับ key ใน `screens` ของ features.json
- `title` ของ board = `"<รหัส> <ส่วน> · <ชื่อหน้า>"` เช่น `"1.3 แนบใบเสร็จ"`, `"0.4 Web · หน้าสินค้า (Yuwell 7F-5W)"`
- ชื่อไฟล์เป็นภาษาอังกฤษแบบ PascalCase คั่นด้วย `-` เช่น `Warranty-Receipt.dc.html` และหน้าจอแรกต้องชื่อ `Main.dc.html`

## ต้องมีอะไรในแต่ละหน้าจอ

- **ข้อมูลจริง** จากเว็บเดิมของลูกค้า เช่น ชื่อสินค้า ราคา เงื่อนไข เบอร์โทร สาขา ข้อมูลที่ยังไม่รู้ใส่ `[วงเล็บ]` อย่าใส่ lorem ipsum หรือตัวเลขที่แต่งขึ้น ข้อมูลตัวอย่างใน back office (ชื่อลูกค้า, ยอดขาย) ทำได้ แต่ต้องเขียนในโน้ตว่าเป็นข้อมูลตัวอย่าง
- **รูปสินค้า** ใช้กล่องสีเทาพร้อมป้าย ถ้ายังไม่มีรูปของลูกค้า
- **กดได้ (`is_interactive: true`) ทุกหน้า** ปุ่มหลักลิงก์ไปหน้าถัดไปใน flow ด้วย `<a href="Next.dc.html">` หน้า back office ก็ต้องกดได้ (tab, filter, เปิดรายการ) อย่าทำเป็นภาพนิ่ง ลิงก์ที่ยังไม่มีปลายทางให้ทำเป็นข้อความธรรมดา อย่าใช้ `href="#"`
- **ภาษา** ตามที่ผู้ใช้เลือกในขั้นที่ 0 ใช้ฟอนต์ที่รองรับไทย เช่น IBM Plex Sans Thai, Noto Sans Thai, Anuphan
- **ปุ่มกดใหญ่อย่างน้อย 44 px** และหน้าจอละหนึ่งปุ่มหลัก

## ป้ายเฟสบนหน้าจอ

- **ทั้งหน้าเป็นฟีเจอร์ที่ไม่ใช่ MVP** ติด badge มุมบน (เช่น "Phase 1", "Later") และใส่เฟสไว้ใน title ของ board
- **บางส่วนของหน้าจอ MVP เป็นเฟสหลัง** (การ์ด, ปุ่ม, tab) ติด badge เล็ก ๆ ที่ส่วนนั้น `check` จะบอกเป็น INFO ว่าหน้าจอไหนมี MVP ปนกับเฟสหลัง
- ปุ่มหรือเมนูที่ไม่มีฟีเจอร์ไหนรองรับ ให้เอาออก อย่าวาดเผื่อไว้

## State ระหว่างหน้าจอ

แต่ละ board เก็บ state ของตัวเอง ค่าที่ผู้ใช้เลือกในหน้าหนึ่งจะไม่ส่งต่อไปอีกหน้า ดังนั้น:
- flow ที่แยกทาง (เช่น บริการที่ต้องมัดจำ กับที่ไม่ต้อง) ให้วาดแยกเป็นหน้าจอ หรือทำเป็น `<sc-if>` สองแบบในหน้าเดียวพร้อมปุ่มสลับ
- การกระทำที่กลับมาหน้าเดิม (เช่น เลื่อนนัด) ให้ทำเป็น sheet หรือ dialog ในหน้าเดิม อย่าลิงก์กลับเข้า flow จองใหม่ ไม่งั้นจะกลายเป็นจองซ้ำหรือจ่ายซ้ำ
- หน้าที่ต้องแสดงผลลัพธ์จากหน้าก่อน ให้ใส่ข้อมูลตัวอย่างที่สอดคล้องกับ flow หลักตรง ๆ
- วาดสถานะผิดพลาดที่สำคัญของ flow หลักด้วย เช่น ชำระเงินไม่สำเร็จ, QR หมดอายุ, ไม่มีช่วงเวลาว่าง

## หน้าจอที่ไม่ได้วาด

ถ้าผู้ใช้จำกัดจำนวนหน้าจอ ให้วาดเฉพาะ flow หลัก ส่วนที่เหลือใส่ใน `screens` พร้อม `"drawn": false` แล้ว feature list จะแสดงว่า "ยังไม่ได้วาด" ซึ่งดีกว่าปล่อยให้ฟีเจอร์ MVP ไม่มีหน้าจอเลย

## โน้ต (sticky) บน canvas

ใช้ sticky สำหรับเรื่องที่คนดู canvas ต้องรู้:
- **readme** (สีเทา, มุมขวาบน): แหล่งข้อมูล + วันที่เปิดดู, ความหมายของ `[วงเล็บ]`, ข้อมูลตัวอย่าง, รูปที่ต้องเปลี่ยน, ภาษาของข้อความจริง
- **การตัดสินใจที่ต้องทำก่อน** (สีฟ้า) วางข้างหน้าจอที่เกี่ยวข้อง เช่น "ต้องเลือกรูปแบบ QR ก่อนสั่งพิมพ์กล่อง"
- **prototype only** (สีเทา): บอกว่ายังไม่ได้เชื่อม payment, LINE หรือระบบอื่นจริง
- **research** (สีเขียว): หน้าจอไหนมาจากการดูแอปอ้างอิง และดูแหล่งที่มาได้ที่ tab Feature list

## ลำดับการทำ

1. canvas.json + Main.dc.html
2. หน้าจอที่เหลือทีละไฟล์ ตามลำดับ flow
3. Feature-List.dc.html สร้างจาก script ด้วย `--canvas` เพื่อให้แก้ความสูงของ board ใน canvas.json ด้วย ทำหลังสุดเพราะต้องใช้รายการ screens ที่ครบแล้ว และต้องรันใหม่ทุกครั้งที่แก้ features.json
